# Разбор идеи и техническое решение

## 1. Что выяснилось при разведке

Прежде чем предлагать варианты, я прощупал все источники из идеи. Результат
поменял оценку задачи целиком: то, что выглядело как «парсинг сайта», оказалось
выгрузкой из открытого API.

| Источник | Что оказалось |
|---|---|
| `mibf.info` | Сайт на Tilda. Статика, участников и программы там нет — только афиша и партнёры |
| `events.mibf.info/2026` | SPA на Nuxt. **В бандле нашлись эндпоинты `/api/locations`, `/api/events`, `/api/events/<id>`** |
| API программы | 509 событий с описаниями, спикерами, организаторами, на трёх языках (ru/en/zh) |
| API карты | **243 участника со стендами** — тот самый список участников, которого нет на сайте |
| Мастерплан SVG | 6,4 МБ, но **весь текст переведён в кривые**: ни одного `<text>`. Названия стендов оттуда не вытащить |
| `vkvideo.ru/@mmkya` | Редирект + рендеринг скриптами. Одним запросом список роликов не забрать |
| Пресс-релиз | PDF на Яндекс.Диске, 13 страниц, забирается публичным API диска |

Единственная защита API — проверка заголовка `Referer`. Без него `401 Access Denied`,
с ним всё отдаётся без ключей и лимитов.

**Главный вывод:** Selenium и Playwright для этой задачи не нужны нигде, кроме VK.
Всё собирается обычными HTTP-запросами за минуты.

## 2. Уточняющие вопросы

Работу это не блокирует — там, где ответа не было, я взял разумное умолчание
и пометил его. Но на эти вопросы стоит ответить, чтобы понять, что делать дальше.

1. **Что это за проект по смыслу?** Разбор-однодневка под конкретную ярмарку 2026,
   или заготовка, которую вы каждый год перезапускаете (и тогда стоит сразу
   вынести год в конфиг)? Я сделал второе: год — параметр.
2. **Контакты участников — публиковать или держать при себе?** 243 организации,
   у большинства есть сайты, почты и телефоны. Собрать их скиллом `contact-scraper`
   — час работы. Но публичная страница с почтами издательств — это уже
   инструмент для рассылок, и вопрос, нужен ли он на сайте или это внутренний файл.
   **Пока не публикую**, собираю только соцсети спикеров, как вы просили.
3. **Сколько тратить на XMLRiver?** Полный прогон по всем книгам и спикерам —
   около 1500 платных запросов. Я запустил полный, но если бюджет ограничен,
   разумно ограничиться теми, кто упоминается больше одного раза.
4. **Репозиторий публичный?** Если да, `.env` и `data/raw/` должны остаться
   в `.gitignore` (уже так).

## 3. Три варианта реализации

### Вариант A — статический сайт из выгрузок (выбран, сделан)

Скрипты выкачивают данные в JSON, генератор собирает готовый HTML в `site/`,
папка кладётся на GitHub Pages. Никакого сервера, никакой базы.

- **Плюсы:** бесплатный хостинг, мгновенная отдача, ничего не ломается, весь
  результат виден в git, 509 страниц событий индексируются поиском.
- **Минусы:** обновление — это пересборка и коммит; живого поиска по серверу нет
  (но клиентского хватает на 509 записей).
- **Трудозатраты MVP:** 6–8 часов. **Сделано.**

### Вариант B — сайт на бэкенде (FastAPI + SQLite)

Данные в базу, страницы рендерятся на лету, есть админка и живой поиск.

- **Плюсы:** можно править контент руками, добавлять записи, вести аналитику
  посещений, публиковать обновления без пересборки.
- **Минусы:** нужен VPS и присмотр; для сайта, который читают, а не редактируют,
  это лишний слой.
- **Трудозатраты:** +12–16 часов к варианту A. **Оправдан, только если сайт живёт
  дальше одной ярмарки и его правит не программист.**

### Вариант C — исследовательский пайплайн без сайта

Только сбор: XLSX с участниками, контактами и книгами, отчёты в Markdown.

- **Плюсы:** быстро, дёшево, годится для рассылки по издательствам.
- **Минусы:** ничего не опубликовать, публичной ценности нет.
- **Трудозатраты:** 3–4 часа. **Имеет смысл как дополнение к A**, если нужны
  контакты для аутрича (скилл `email-outreach` подхватит XLSX как есть).

## 4. Стек

| Слой | Чем | Почему так |
|---|---|---|
| Сбор данных | `requests` + сессия с `Referer` | API открытое, браузер не нужен |
| Поисковая выдача | XMLRiver, пул на 10 потоков | по правилу проекта: не Selenium для Google/Яндекс |
| Разбор текста | бесплатные модели OpenRouter | механическая классификация «книга / не книга» — 629 строк |
| Тексты для людей | пишутся вручную | пресс-релиз и разбор рынка подписок читает человек |
| Генерация сайта | чистый Python + f-строки | шаблонизатор на 9 страницах — лишняя зависимость |
| Фронтенд | один CSS-файл, ванильный JS | фильтры на 509 записей работают мгновенно, светлая и тёмная темы |
| Хостинг | GitHub Pages | бесплатно, из того же репозитория |

## 5. Риски

| Риск | Насколько вероятен | Что делаем |
|---|---|---|
| **API закроют или сменят защиту** | Средний. Сейчас достаточно `Referer`, но это может стать токеном | Все сырые выгрузки лежат в `data/` и в git — сайт пересобирается без сети |
| **Юридическая сторона** | Средний. Описания событий — авторский текст организаторов | Мы даём выдержки и обязательную ссылку на первоисточник в каждой карточке; в подвале дисклеймер, что сайт не официальный. Если организаторы возразят — описания заменяются на краткие пересказы |
| **XMLRiver даёт мусор** | Высокий на однословных названиях: «Гамлет» найдётся у всех | Ссылки помечены как найденные поиском, приоритет — «Дом книги»; спорные названия отсеиваются по числу упоминаний |
| **Модель ошибается, считая книгой не книгу** | Средний | Промпт явно перечисляет, что книгой не является (издательства, премии, площадки); ошибки видны глазами в `data/books.json` |
| **Соцсети спикеров: однофамильцы** | Высокий для распространённых имён | В запрос добавлен контекст «писатель / автор / блогер»; берутся только профильные домены |
| **VK не отдаёт видео без токена** | Реализовался | Страница видео сделана как навигация по каналам; полный список — после `VK_SERVICE_TOKEN` |
| **Персональные данные** | Низкий | Публикуются только публичные профили публичных спикеров; контакты участников не публикуются |

## 7. Что осталось за рамками

- **Лекции спикеров на YouTube.** Скрипт `enrich_youtube.py` готов и проверен,
  но на середине прогона по 1195 именам на счету XMLRiver кончились деньги.
  После пополнения — один запуск, страницы персон подхватят ролики сами.
- **Прямые ссылки на ролики VK.** Список записей на сайте есть и привязан
  к событиям, но адреса вида `video-XXX_YYY` VK без авторизации не отдаёт.
  Нужен `VK_SERVICE_TOKEN` — тогда `fetch_vk_video.py` заменит ручной импорт.
- **Контакты участников.** Почты и телефоны 233 организаций уже лежат
  в `data/exhibitors.json`, но на сайт не выведены — см. вопрос 2.
- **Публикации участников в соцсетях.** Технически это `wall.get` по найденным
  сообществам, упирается в тот же VK-токен.
- **Расшифровки трансляций.** 39 записей, суммарно около 32 часов эфира.
  Локальный GigaAM расшифровывает их бесплатно, и тогда к каждому событию
  добавляется не анонс, а то, что там реально сказали. Это самое сильное,
  что можно сделать с сайтом дальше: 5–8 часов.
